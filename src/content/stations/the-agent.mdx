## What we plug together

1. **The context prompt**: who the robot is, what it cares about, what it must never do
2. **The skills from Station 4**, handed to the model as function definitions
3. **The realtime API**, listening and answering continuously instead of once per question

## The loop

The agent does not run a program. It runs a conversation with a robot attached.

1. Perception describes the situation in words: a person is visible, three metres ahead
2. The model reads that together with the prompt and decides
3. It calls a skill: `wave`, `walk_to`, `look_at`
4. The robot executes, and what happened goes back in as the next input
5. Back to step 1

Nowhere in this loop is there a list of situations. Step 2 is the entire difference.

## The example order

> "Walk around until you see someone. When you recognise a person, wave at them."

That is the complete specification. No states, no transitions, no edge cases.

## What still does not work

- The model is slow next to a control loop, so reflexes stay hard-coded. Balance is not up for
  discussion
- It will call a skill in a situation the skill was never built for
- It cannot improvise an ability that no skill exposes
- The same situation twice does not guarantee the same decision
