## The four building blocks

Every AI agent, whether it lives in a browser tab or inside a humanoid robot, is assembled from
the same four parts.

- **LLM** — the language model. It reads the situation and proposes what to do next.
- **Memory** — what happened so far, so the agent does not start from zero on every step.
- **Reasoning** — breaking a vague order into a sequence of concrete steps.
- **Skills** — the things the agent can actually *do*. This is the word to hold on to.

## Skills you already know, and skills you don't

A coding assistant has skills too. They just act on files instead of on the world.

| Skill in the web and PC world | Skill in the embodied world |
| --- | --- |
| Read a file | Look through the camera and name what is there |
| Search the web | Walk to a different room and scan it |
| Write a file | Pick up an object and put it somewhere else |
| Call an API | Wave, point, hand something over |

The pattern is identical. Only the consequences differ: a wrong file write is undone with one
command, a wrong arm movement is not.

## How robots are programmed today

Almost every robot in production runs a **state machine**: a fixed set of situations, and fixed
rules for moving between them. Try the one below — it is the "walk around and wave at people"
task, written the traditional way.

Notice what you cannot do: anything that is not already a button. There is no event for "the
person is waving first", no event for "two people arrived at once". Every single case had to be
imagined by a developer, in advance, and typed out.

That is the limit an agent is meant to break. We come back to exactly this task in Station 5.
